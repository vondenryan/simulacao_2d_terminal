GraphicEngine

Package: com.simulacao_terminal.engine

Description: Handles rendering the game to the terminal and physics simulation. Runs two threads: one for physics updates and one for rendering.

Overview

GraphicEngine is the core of the game loop. It manages:

  • Rendering the map and player to terminal with ANSI colors
  • Physics simulation with collision detection
  • Camera/tracking the player position

Methods

start()

Description: Starts both the render thread and physics thread. Returns immediately.

renderLoop()

Description: Main rendering thread. Outputs the current frame to terminal.

Behavior:

  1. Waits for frameToRender to update
  2. Compares with lastFrame to avoid duplicate output
  3. Resets terminal cursor position
  4. Prints current frame
  5. Sleeps for frame_time milliseconds

Optimization: Only renders when frameToRender changes, avoiding unnecessary console output.

mainLoop()

Description: Main physics update thread. Calls updatePhysics() and builds the render frame.

Behavior:

  1. Runs while gameState.isRunning() is true
  2. Updates player physics
  3. Calculates visible viewport around player
  4. Builds frame string with block rendering
  5. Sets frameToRender for renderLoop
  6. Sleeps for frame_time milliseconds

updatePhysics()

Description: Updates player position with sub-stepping for accurate collision detection.

Sub-stepping: 3 sub-steps per frame for smoother physics

Physics Order:

  1. Gravity: velY += GRAVITY / subSteps
  2. Velocity Clamping: clamp to [-1.8, +1.8]
  3. X Movement: Apply stepX, check collision
  4. Y Movement: Apply stepY, check collision
  5. Collision Response: Stop velocity, adjust position

Frame Building

StringBuilder frame = new StringBuilder();
for (int lin = topSide; lin < bottomSide; lin++) {
    for (int col = leftSide; col < rightSide; col++) {
        if (col == playerX && lin == playerY) {
            frame.append("\033[31mO\033[0m");  // Player
        } else {
            int blockVal = map[lin][col];
            frame.append(displayConfig[blockVal]);  // Block color
        }
    }
    frame.append("\n");  // Newline for each row
}

Double Buffering

private volatile String frameToRender = "";  // Write buffer
// renderLoop reads from frameToRender

Uses volatile to ensure frameToRender updates are immediately visible to renderLoop.

Threading Note: The current implementation runs physics and rendering in separate threads but modifies the player object directly. Consider adding synchronization if InputService also modifies player directly.
