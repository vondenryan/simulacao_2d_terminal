InputService

Package: com.simulacao_terminal.services

Description: Processes keyboard input from GameState and applies it to Player physics. Runs in a separate thread and works with GraphicEngine to move the player.

Overview

InputService reads keystrokes from GameState and translates them into player movement. It handles jumping, horizontal movement, and deceleration.

Methods

start()

Description: Starts the input processing thread. Returns immediately.

inputProcessingLoop()

Description: Main loop that reads input from GameState and updates player physics.

Behavior:

  1. Reads lastInput from GameState with synchronization
  2. Clears lastInput in GameState
  3. Processes key based on value
  4. Updates player velocity
  5. Handles deceleration when no input
  6. Waits for frame time before next iteration

Input Key Mappings

KeyActionEffect on Player
'w', 'W', ' 'JumpSets velY to JUMP_POWER (-0.9) if on ground
'd', 'D'Move RightAdds ACCELERATION (0.9) to velX
'a', 'A'Move LeftSubtracts ACCELERATION (0.9) from velX
'°' (null)No InputApplies DECELERATION to velX

Deceleration Logic

When no key is pressed, the player slows down based on whether they are in the air or on ground:

ConditionDeceleration
AirborneDECELERATION / 2.5 = 0.16
On groundDECELERATION = 0.4

Ground deceleration is higher, making movement snappier when on terrain.

Velocity Clamping

InputService sets velocity directly. GraphicEngine clamps final velocities to [-1.8, +1.8].

Thread Synchronization

// Writes from InputController:
synchronized (gs) {
    gs.lastInput = c;
}

// Reads in InputService:
synchronized (gameState) {
    keyPressed = gameState.lastInput;
    gameState.lastInput = '\0';
}
Thread Safety: Both InputController and InputService synchronize on the same GameState object, ensuring safe concurrent access to lastInput.

Frame Timing

The loop sleeps for gameState.getFps() milliseconds each iteration, typically 33ms for 30 FPS.
